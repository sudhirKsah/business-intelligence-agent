Decision Log

Project: Skylark Drones monday.com BI Agent

Goal And Scope

I prioritized one explainable end-to-end path over a broad analytics product: founder question, validated plan, live read-only monday.com data, normalization, deterministic calculation, then a concise answer with insight, caveats, and retrieval time.

The committed catalog is Open Deals pipeline/health, Work Order inclusive-GST financials, execution/billing exceptions, and exact-sector comparisons. Weighted forecasting, excluded-GST analysis, overdue logic, dashboards, durable chat history, and row-level cross-board journeys are deliberately incomplete.

Assumptions

  • Open defines active pipeline. Pipeline time means Tentative Close Date; calendar quarters use Asia/Kolkata and inclusive boundaries.
  • Masked Deal value has unknown currency/scale, so it is never labeled INR or revenue. Work Order financials use direct inclusive-GST source columns; blanks are unknown, not zero.
  • Every monday item is retained by default. Totals are board-item totals because duplicate-looking records cannot safely be deleted without a business key.
  • Exact normalized sectors are comparable across boards, but rows are not joinable. Energy requires clarification to Renewables, Powerline, or both.
  • Public evaluation uses server-side credentials. Runtime code is query-only and exposes no token.

Data Handling

Null/blank/NA stays missing, zero stays zero, invalid numeric text never becomes zero, negatives remain, and month-only text receives no invented year. Embedded Deal headers are excluded and counted. Possible duplicates remain with a no-deduplication caveat. Tender/DSP stay source values but are flagged as potentially non-sector labels. GraphQL errors or incomplete pages invalidate the request; partial monday data is never aggregated.

Leadership Updates

I interpret this as a short defensible brief: summary, key numbers, one or two calculated observations, material data gaps, and retrieval details. Normal answers use that structure. A slide/report generator was deferred because presentation breadth should follow metric reliability.

With More Time

I would first establish governed metric definitions and an authoritative Deal-to-Work-Order key; then add authenticated multi-tenant access, short-lived caching, observability, source update timestamps, richer cohort/trend analysis, and broader end-to-end/accessibility tests. Dashboards and downloadable leadership reports would follow those foundations.
